# 向量库瘦身：chromadb 依赖剪枝实测结论

> 2026-10-06 实测。**本文修正了同日早些时候"删 kubernetes+grpc 可省 84M"的错误结论。**
> 所有结论均来自跑完整 `scripts/build-backend-runtime.sh` 的真实构建，非推测。

## 一、先说被推翻的结论

早些时候的结论是「装完 chromadb 后 `rm -rf site-packages/kubernetes* grpc*` 即可省 84M」，
并附了「import 通过 + 真实 upsert/query 通过 + 928 测试全绿」的证据。

**这些证据全部是假阳性。** 两个独立 bug 叠加，导致删不掉而且看不出来。

### bug 1：解释器兜底 import

`backend-runtime/bin/python3` 的 `sys.path` 里，runtime 自己的 site-packages
在 **index 5**。`PYTHONPATH` 确实排在 index 1 优先级更高，但：

> 一旦目标包在「删过的副本」里不存在，import 机制就**回落到 runtime 自己的真包**。

实测证据：把 `chromadb_rust_bindings` 整个目录移走后，跑"探针"仍然返回 `OK`，
且 `chromadb_rust_bindings.__file__` 指向
`.../backend-runtime/lib/python3.12/site-packages/chromadb_rust_bindings/__init__.py`
—— 根本不是我们测试的那份。

**所以「删掉必需包后仍然通过」是必然的，探针根本不具备检测能力。**

修正：探针必须用 `-I`（同时忽略 `PYTHONPATH` 与用户 site-packages），
并断言 `__file__.startswith(sys.prefix)`。已实测 `-I` 下删掉 rust_bindings
立刻抛 `ModuleNotFoundError`，探针这才有效。

### bug 2：shell glob 中断（`set -e`）

剪枝循环用了：

```bash
for target in "$site_dir/$pkg" "$site_dir/$pkg.py" "$site_dir/${pkg}-"*.dist-info
```

glob 无匹配时 bash 抛 `no matches found`，配合脚本头的 `set -euo pipefail`
**直接中断整个脚本** —— 后续的包根本没轮到删，而脚本以"成功"退出。

**两层失效叠加 = 一个包都没删掉，还打印"已剔除"。**

修正：剪枝一律用

```bash
find "$site_dir" -maxdepth 1 \( -name "$pkg" -o -name "$pkg.py" -o -name "${pkg}-*.dist-info" \) -print
```

`find` 无匹配时静默返回 0，行为可预期。

## 二、真实结论：只有 kubernetes 能删

### grpc 删不掉（这是关键修正）

`grpc` 出现在**顶层 import 链**上，不是可选路径：

```
chromadb/__init__.py
  → chromadb/telemetry/opentelemetry/__init__.py:13
      from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
  → opentelemetry/exporter/otlp/proto/grpc/trace_exporter/__init__.py:11
      from grpc import ChannelCredentials, Compression, StatusCode
```

实测：删掉 grpc 后构建期探针直接失败

```
ModuleNotFoundError: No module named 'grpc'
```

telemetry（遥测）这条路 **telemetry 不是可选开关**，chromadb 启动即走。
所以 `grpcio>=1.58.0` 写死在 `METADATA:24` 是有实际理由的，删不掉。

### kubernetes 可以删

唯一引用在分布式路径：

```
chromadb/segment/impl/distributed/segment_directory.py:4
    from kubernetes import client, config, watch
chromadb/test/segment/distributed/test_memberlist_provider.py:5
```

本地 `PersistentClient` 不导入该模块 → 删除安全。

实测：`segment_directory.py` 属于 `segment/impl/distributed/` 子包，
只有走多节点协调时才会被 import。

## 四、已落地的脚本改动

`backend/scripts/build-backend-runtime.sh`：

- **6.1** 剪 kubernetes，用 `find` 而非 glob；剪完**按名复查**，
  `kubernetes` 仍在则 `exit 1`（防止再次静默失效）。
- **6.2** 隔离模式探针：`-I` + `sys.prefix` 断言 + 真实
  upsert/query/where-filter/delete/delete_collection 链路。
  失败 `exit 1` 并提示回滚。

## 五、体积账（修正后）

| 方案 | 省下 | 状态 |

## 六、方法论教训

**「跑通了」不等于「验证有效」。** 本次两个 bug 的共同点是：
验证手段本身失效，却给出了绿色的假信号。

可复用的判据：
1. 验证"删除某物是否安全"时，**必须证明验证工具本身能抓到失败**（mutation test）。
   本次删除 `chromadb_rust_bindings` 后探针仍 OK，即为 mutation 未被捕获。
2. 用 `PYTHONPATH` 指向副本做"删包实验"时，解释器兜底路径会让实验失效。
   必须 `-I` + 断言 `__file__` 归属。
3. `set -e` 脚本里 shell glob 无匹配会中断整个脚本 —— 用 `find` 代替。
4. 「构建脚本打印成功」不等于「改动生效」，必须有独立的、按名的复查。
