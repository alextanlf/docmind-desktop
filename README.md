# DocMind

DocMind 是一个运行在 macOS 或 Windows 本机的个人知识库助手。它把网页、PDF、Word、Markdown 和语雀文档集中到一个地方，让你可以浏览、整理和提问，并且每个回答都尽量带上来源引用。

设计上以**本地优先**为准：文档、索引和对话默认只留在本机；需要联网的地方（云端模型、联网搜索、语雀同步）都逐项可选，并且能说清数据去了哪里。

## 它能做什么

- 导入网页、PDF、Word、Markdown 和 HTML 文件；`.pages` 与 TeX 由插件提供
- 创建纯本地知识库，也可连接语雀仓库浏览和同步文档
- 建立本地索引（词法 + 向量），快速检索资料
- 基于你的资料回答问题，并显示引用来源
- 选择云端模型或本地 Ollama 模型；模型可增删改，并随时切换当前使用的那一个
- 图里的内容也进检索：插图提取、图片文字识别、图表语义描述
- 可选地维护本地网页语料、长期记忆和文档关系图

## 适合谁

适合希望把分散资料整理成私人知识库的个人用户，尤其是经常阅读长文、处理 PDF、使用语雀，并且希望回答可追溯的人。

## 支持的内容

| 类型     | 说明                                     | 限制                        |
| -------- | ---------------------------------------- | --------------------------- |
| 网页     | 通过 HTTP/HTTPS 链接导入文章             | Markdown 转换后不超过 20 MB |
| PDF      | 导入本地 PDF                             | 单个文件不超过 100 MB       |
| Word     | 导入 `.docx`                             | 单个文件不超过 100 MB       |
| Markdown | 导入 UTF-8 编码的 Markdown               | 单个文件不超过 20 MB        |
| HTML     | 导入 `.html` / `.htm`                    | 单个文件不超过 20 MB        |
| 语雀     | 可通过网页登录或 API Token 同步已有仓库  | 两种连接方式均为可选        |
| 飞书     | 绑定自定义机器人 Webhook，接收导入的文档 | 可选                        |
| 其他     | `.pages`、TeX 等由插件提供的格式         | 需先安装对应插件            |

一批文件可以一起导入（目录批次）。导入前会先跑候选清单，逐个页面说清**哪些内容要进来、哪些没进来、各自为什么**，你确认的清单与真正导入的内容由 sha256 校验绑定 —— 原件变了就不导入，而不是悄悄导入别的东西。

**原件留在原地。** 导入时应用直接读你磁盘上的文件，只把转换后的 Markdown 存进应用，不再为你已有的文件复制一份副本。原件被改动、移动或删除时会明确提示，应用自己永不写、永不删你的原件。

## 快速开始

### 1. 准备环境

需要 macOS 或 Windows，以及：

- Node.js 20 或更高版本
- Python 3.11 或更高版本
- [uv](https://docs.astral.sh/uv/)

Windows 上的 shell 脚本需要在 Git Bash 或 MSYS2 里执行。

### 2. 安装依赖

在项目根目录执行：

```bash
npm install
./scripts/setup-backend.sh
```

### 3. 启动应用

```bash
npm run dev
```

### 4. 首次配置

启动后，在设置中选择模型服务，并填写 API Key。DocMind 支持 DeepSeek、Qwen、OpenAI 和自定义 OpenAI-compatible 服务。**每个服务商各存各的 Key** —— Key 不通用，换一家要另填一份，切回原来那家会自动恢复。设置里的「对话模型」是一份**已配置模型列表**，可以增删改，并指定当前使用哪一个。

API Key 只保存在系统凭据存储中（macOS Keychain / Windows 凭据管理器），不会写入 SQLite、诊断信息或日志。Windows 上的凭据被显式限制为仅本机保存，不会随域漫游配置同步到其他电脑。

进入工作台不要求绑定语雀。需要使用时，在设置中按需选择：

- **语雀网页**：打开可见浏览器完成登录，适合没有个人访问令牌的账号
- **语雀 API**：填写语雀个人访问令牌并验证；验证通过后，语雀读写会优先使用 API
- **飞书绑定**：填写飞书自定义机器人的 Webhook，验证成功后会发送一条测试消息

语雀 API Token、飞书 Webhook 和模型 API Key 一样只保存在系统凭据存储中。第一次需要语义检索时，应用会提示准备 embedding 模型（默认 `BAAI/bge-m3`，下载体积约 400 MB）。

应用内「新建知识库」默认创建纯本地知识库，文档会保存在本机并建立本地索引，不要求登录语雀。已绑定的语雀知识库仍会显示在列表中，可以继续同步远端内容。

## 使用本地模型

DocMind 支持任意 OpenAI 兼容的本机推理服务，例如 [Ollama](https://ollama.com/)（默认端口 11434）、[LM Studio](https://lmstudio.ai/)（默认端口 1234）以及 llama.cpp、vLLM、Jan 等。

在设置中填入服务地址，本地模型会从该服务已加载的模型列表中选择。DocMind 不提供模型下载，请先用相应的工具把模型加载到服务里。

「本地运行与路由」页负责本地模型、云端回退策略与本地数据。出于安全考虑，本地服务只允许通过本机回环地址（`localhost`、`127.0.0.1`、`::1`）访问，且不校验其名称是否合法。

## 联网搜索

需不需要联网**由模型自己判断**：DocMind 把 `web_search` 交给对话模型，模型在文档片段不足以回答时自行发起检索，一轮没搜到可以换词再搜（最多 3 轮）。你也可以自己控制——每条消息都能选择本次不联网，回答下方在没有引到任何来源时会给出「联网搜索」按钮，点一下强制补搜一次。点「联网搜索」时不会被本地语料挡住。

搜索来源按以下顺序尝试：

1. **模型内置联网**：Qwen（阿里云百炼）、OpenAI、智谱 GLM、小米 MiMo 的模型自带联网能力，无需额外配置
2. **Tavily**：内置联网不可用时兜底，**无需注册、无需 API Key**（免密钥模式）；以前填过 Tavily Key 的安装会继续用自己账号的额度

搜索结果会作为引用来源展示，并可以挑选后加入知识库。

DeepSeek、Kimi 等模型会直接跳到 Tavily——它们即使在厂商侧有联网，也不会返回可枚举的来源列表，因而没法参与引用与本地资料的融合。

搜索词会先被改写成最多 3 条并行检索、再合并去重，以提升召回。本地来源只在降级时使用，不会被上游不可用直接删掉。

## 本地网页语料

除了一次性导入，「网页语料」页维护一份**长期的本地网页索引**：从你自己的数据里挖候选（文档里出现过的网址、之前抓过的站），也可以自己提名，由离线信号给出「该不该收录」的证据。

- 候选清单**带上证据**，可审计，不依赖上游服务
- 抓取在后台进行，页数上限不再由「你愿意等多久」决定，可以随时停止
- 增量刷新：没变的页面不重抓不重写，消失的页面按证据清理
- 抓取失败带上真实原因；每个主机有礼貌节奏，并且会先做域名可达性探测，把「抓不到」拆成可决策的原因

## 检索与回答

- 词法与向量两条通道**真融合**：词法有命中时两条通道一起决定排序
- **向量救援**：中文问句问英文正文时 BM25 会结构性地搜不到，向量通道负责补上
- 中文问句 × 英文正文的检索缺口有量化用例留档（BM25 0/10，向量 10/10）
- 图里的内容也进检索：插图提取、图片文字识别（OCR），以及可选的图表语义描述
- 首次进入工作台不是空文本框：提供一键话题与三步说明

## 隐私和数据归属

- 文档索引和缓存默认保存在本机应用数据目录
- API Key、语雀 Token、飞书 Webhook 仅保存在系统凭据存储（macOS Keychain / Windows 凭据管理器）
- **导入不复制你的原件**：应用只读磁盘上的原件，永不写、永不删；删除文档只动应用自己那份转换结果
- 联网搜索由模型按需发起，也可以逐条消息关闭；发生检索时应用按「模型内置联网 → Tavily」的顺序访问搜索服务，没有可用来源时会直接跳过联网
- 搜索结果由搜索服务自己抓取网页，DocMind 不直接访问目标网站，目标网站不会看到你的网络地址
- 导入网页时，应用会从该页面引用的图片主机下载图片（用于识别图内文字并展示原图）。这一步会直接访问那些图片主机，它们因此能看到你的网络地址 —— 与上面的搜索结果链路不同。指向本机与内网的图片地址会被拒绝
- 「用视觉模型描述图表」默认**关闭**。开启后，图里没有文字的插图（状态转移图、曲线图、示意图）会被**发送到当前使用的模型服务商**，用来生成一句可检索的描述。这是唯一一处会把文档内容发给第三方的处理步骤，所以必须由你显式打开
- 本地文件路径不会进入回答中的引用或持久化内容

## 插件

插件层存在的理由是**体积**：不是应用必需、也不是多数用户需要的能力，不该进安装包。

在设置 →「插件」里可以搜索、配置、启用或移除插件，并可以增删插件自带的文档格式。DocMind 的源码一行都不用改。仓库内自带两个官方插件：

- `plugins/docmind-pages` —— `.pages` 文档
- `plugins/docmind-tex` —— TeX 文档

写自己的插件见 [插件开发指南](docs/插件开发指南.md)：在包里声明一个 `docmind.plugins` entry point 即可。

## 归档与删除

删除文档改为**归档**：内容都还在，随时可以恢复。永久删除另外放在「已归档的文档」页，需要显式操作。移除远端知识库与文档时同样只删本地、可恢复，并支持按远端目录批量处理。

## 常见问题

### 启动失败

先确认 Node.js、Python、uv 和项目依赖都已安装。如果提示端口被占用，通常是 `127.0.0.1:18900` 已被其他进程使用。

### 打开后显示后端不可用

检查后端依赖是否完整。必要时重新运行：

```bash
./scripts/setup-backend.sh
```

### 有可以下载的安装包吗

当前版本以本地开发方式运行，暂不提供签名后的 `.dmg` 或 `.app` 安装包。本地打包可用：

```bash
npm run desktop:package
```

## 开发者

运行完整检查（后端 pytest + ruff，前端 vitest + typecheck + lint + format + build + e2e）：

```bash
npm run verify
```

只跑前端：`npm run desktop:test`；只跑后端：`cd backend && uv run pytest`。

开发约定写在 [AGENTS.md](AGENTS.md)，每条都来自一次真实事故，改动前值得先读。

应用图标「折页星火」的几何与色板固化在 `scripts/generate-icons.mjs`。调整图标后重新生成 SVG、16–1024 PNG、`.icns`、`.ico` 与渲染层图标资源：

```bash
npm run icons:generate
```

Dock 与应用包用「macOS 画布版」（`build/icons/png/docmind-icon-mac-512.png`、`DocMind.icns`）：1024 画布内实体只占 824，四周各留 100 透明边距，和系统自带图标的占位一致。窗口图标、favicon 等仍用铺满画布的版本（应用内侧边栏只保留 DocMind 文字，不再显示图标）。

macOS 上的图片文字识别小程序（通用二进制 arm64 + x86_64）由源码编译产出，不提交二进制：

```bash
./scripts/build-vision-ocr.sh
```

### 提交前扫描

本仓库是公开仓库，所以提交前会拦下本机绝对路径（`/Users/<用户名>/…`）、本机专属目录名、常见密钥形态（`sk-`、`tvly-`、`AKIA`、`ghp_` 等）与个人邮箱。钩子在 `.githooks/pre-commit`，克隆后执行一次即可启用（`npm install` 的 `prepare` 也会自动做）：

```bash
git config core.hooksPath .githooks
```

钩子还会对**暂存的文件**单独跑格式检查，只格式化你改过的文件：

```bash
npx prettier --write <文件>…
```

测试夹具里的占位路径（`/Users/x/`、`/Users/private/`、`/Users/someone/` 等）已在白名单内，不会误报。本机专属词（本机目录名、主机名等）不写进仓库，放不受版本控制的 `.git/docmind-scan-terms`，一行一个：

```bash
printf '%s\n' '本机目录名' >> .git/docmind-scan-terms
```

确需提交故意构造的样例时显式绕过：

```bash
DOCMIND_SKIP_SECRET_SCAN=1 git commit ...
```
