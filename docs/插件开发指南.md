# DocMind 插件开发指南

本文档面向想为 DocMind 写集成插件的开发者。写完之后，你的插件会出现在设置页的
**插件** 分区里，用户可以搜索它、配置它、用它导入文档——而 DocMind 的源码一行都不用改。

现有插件见 `backend/app/yuque/`（语雀）与 `backend/app/feishu/`（飞书文档）。

---

## 30 秒上手

在你的包里声明一个 entry point：

```toml
# pyproject.toml
[project.entry-points."docmind.plugins"]
acme = "acme_docmind:plugin"
```

```python
# acme_docmind/__init__.py
from app.plugins import PluginContribution
from app.remote.credentials import CredentialChannelSpec, ProviderCredentialSpec
from app.remote.provider import ProviderCapabilities, ProviderIdentity


class AcmeProvider:
    identity = ProviderIdentity(
        name="acme",
        label="Acme Wiki",
        summary="把 Acme Wiki 页面导入 DocMind",
        icon="library",
        keywords=("acme", "wiki"),
        homepage="https://acme.test",
        version="0.1.0",
        capabilities=ProviderCapabilities(),
    )

    async def close(self) -> None:
        return None


plugin = PluginContribution(
    provider=AcmeProvider(),
    credential_spec=ProviderCredentialSpec(
        provider="acme",
        channels=(
            CredentialChannelSpec(
                name="token",
                label="Acme 访问令牌",
                has_secret=True,
                default_secret_ref="acme:token",
                summary="用个人访问令牌读取 Acme Wiki",
                icon="key",
                keywords=("token", "令牌"),
                hint="在 Acme 后台生成一个访问令牌。",
            ),
        ),
    ),
)
```

装上这个包，重启 DocMind。插件页会多出一张「Acme 访问令牌」卡片，归属「Acme Wiki」，
搜 `acme`、`wiki`、`令牌` 都能命中。

## 概念：什么是一个插件

**一个插件卡 = 一个 provider 的一个凭据通道**，不是整个 provider。

这不是随手定的。`语雀网页登录` 和 `语雀 API` 是用户要**二选一**的两件事（开浏览器 vs 贴令牌），
合并成一张卡就把这个选择藏起来了。同理 `飞书账号授权` 和 `飞书机器人` 也不是一个东西的两项功能。

所以你现在写的 `AcmeProvider` + 它的每个 channel，会各自渲染成一张卡。卡片上的字段全部来自
你自己的声明——插件页不认识任何厂商，也没有硬编码的插件清单。

## 你要实现的两个协议

### 1. `RemoteProvider`

定义在 `backend/app/remote/provider.py`。契约与传输方式无关：你可以用官方 Open API、
浏览器自动化，或者任何别的手段。

必实现的方法（按用途分组）：

| 用途 | 方法 |
|---|---|
| 登录态 | `login_status()`、`begin_login()` |
| 知识库 | `list_repositories()`、`create_repository()` |
| 文档 | `list_documents()`、`create_document()`、`read_document()`、`update_document()`、`delete_document()`、`document_exists()` |
| 生命周期 | `close()` |

可选能力通过 `ProviderCapabilities` 声明，**不要**在客户端按厂商名分支：

```python
ProviderCapabilities(
    browser_install=False,        # 需要本地浏览器驱动登录，且能按需准备 WebDriver
    marker_lookup=False,          # 支持 find_document_by_marker（幂等写入的补偿机制）
    parent_node_write=False,      # 新文档可指定平台原生父容器
    browser_unavailable_code=None, # 缺浏览器时抛出的错误码，UI 据此显示安装按钮
)
```

`browser_unavailable_code` 必须由你声明、客户端不得硬编码。写死一个厂商错误码会让这个组件
对**所有其它插件**都是错的，包括还没被写出来的那些。

### 2. `ProviderCredentialSpec`

定义在 `backend/app/remote/credentials.py`。声明你有几个凭据通道、每个通道怎么验证。

```python
CredentialChannelSpec(
    name="token",              # 内部标识，存 keychain 与 URL 用
    label="Acme 访问令牌",      # 卡片副标题 / 输入框标签
    has_secret=True,           # 是否有密钥；False = 走交互式登录
    default_secret_ref="acme:token",  # macOS 钥匙串条目名
    tester=test_my_token,      # 异步 (secret) -> 账号标签 | None，失败抛 DomainError
    normalizer=normalize_my_url,      # 规范化/拒绝用户输入；SSRF 防线在这里
    secret_placeholder="粘贴访问令牌",   # 输入框占位符
    help_url="https://acme.test/tokens",
    help_label="获取令牌",
    purpose="source",          # "source" 提供文档 / "notify" 推送通知
    summary="用个人访问令牌读取 Acme Wiki",  # 卡片正文，说明效果
    hint="在 Acme 后台生成一个访问令牌。",  # 说明代价
    icon="key",                # 图标键，见下
    keywords=("token", "令牌"),  # 额外的搜索别名
)
```

`purpose` 是**元数据**，会在卡片上显示成一个标签。插件页**不会**按它分区——那正是我们要
去掉的行为（按「知识库来源 / 通知」分区会让机器人 webhook 看起来像第三种导入方式）。

#### 图标键

`icon` 是一个字符串键，由前端解析成字形。目前可用：

| 键 | 用途 |
|---|---|
| `library` | 文档 / 知识库 |
| `key` | 需要密钥的凭据 |
| `login` | 浏览器登录 / OAuth |
| `bell` | 通知 |

传未知键不会崩——前端会退回一个中性的 `Puzzle` 图标。插件作为数据分发，字形表归前端所有。

## 声明信息：什么该你写，什么不该

**所有展示文案都由你声明**，前端和 API 层都不许拼：

- `label` / `summary` / `hint` / `placeholder` / `help_label`
- `icon` / `keywords`
- 错误码 → 中文文案由 `electron/renderer/src/lib/client-errors.ts` 这个字典负责，
  但**平台专属的**错误码常量放在你自己的 leaf 模块里（例如 `app/yuque/codes.py`），
  放进 credentials 或 gateway 都会循环依赖。

一条判据：**文案映射表和安全白名单不算平台逻辑分支**。`isYuqueUrl` 这种域名白名单是安全
代码，别删；但 `if (provider === "yuque")` 这种是耦合，必须消除。

## 通知（可选）

插件可以声明一个通知目标，把导入完成/失败推到平台自己的聊天里。这不是一个额外要求——
只读文档的插件什么都不用实现。

```python
from app.remote.notifications import (
    NOTIFY_ERROR, NOTIFY_INFO, NOTIFY_SUCCESS,
    NotificationEvent, NotificationTarget,
)

def build_my_target(credential_store):
    def _ready() -> bool:
        ...
    async def _send(event: NotificationEvent) -> None:
        ...
    return NotificationTarget(
        name="acme:webhook",
        send=_send,
        is_ready=_ready,
        severities=frozenset({NOTIFY_INFO, NOTIFY_SUCCESS, NOTIFY_ERROR}),
    )
```

放进 `PluginContribution.notifications`，它会注册进和内置插件**同一个** `NotificationHub`，
所以业务代码只调 `hub.notify()`，永远不需要知道消息发去了哪。投递永远是 best-effort。

## 加载与故障

插件在应用启动时从 `docmind.plugins` entry point 组被发现，注册到和内置插件**同一个**
`ProviderRegistry`——所以它走的是完全相同的凭据 / 发现 / 导入路径，没有「第三方专用分支」。

**加载失败不会阻止启动。** 一个坏插件只会让功能退化，不该让整个 app 打不开。失败会被收集，
并在设置页插件区底部以「以下插件加载失败」显示出来：

> 静默失败的插件和从未安装的插件在用户看来一模一样。不显示出来，就等于让用户没法区分
> 「这个集成坏了」和「这个集成不存在」。

entry point 每次进程读取一次。装完插件需要重启，和装任何其他依赖一样。

## 返回什么

entry point 指向的可调用对象可以返回：

- 一个 `PluginContribution`
- 多个 `PluginContribution`（可迭代对象）
- 一个返回上述任一者的工厂函数（延迟初始化）

### `PluginContribution` 字段

| 字段 | 说明 |
|---|---|
| `provider` | 你的 `RemoteProvider` 实现 |
| `credential_spec` | 你的 `ProviderCredentialSpec` |
| `is_configured` | 可选的配置探测闭包。给了就用；不给且声明了 `credential_spec`，注册表自动用「任一声明通道已验证」——**不要**手写逐插件闭包 |
| `notifications` | 可选的 `NotificationTarget` 元组 |

## 几条硬规矩

这些不是风格偏好，违反了会让插件在真实使用中出错：

1. **平台专属逻辑不许进 API 层或同步层。** 能力探测走 `ProviderCapabilities`，
   **禁止 isinstance**。远程绑定是 `(repositories.provider, repositories.remote_id)` 复合唯一。
2. **URL 类凭据必须走 `CredentialChannelSpec.normalizer`。** 这是 SSRF 防线——
   webhook 地址必须在保存前校验域名白名单，不要指望 API 层替你判断 `provider == "..."`。
3. **档位值 / 枚举值用厂商原生字符串，不要再套统一抽象层。** 但也不要把它们下发到前端
   让前端猜。
4. **捕获范围精确到具体异常类。** 把 `except SpecificError` 抄成 `except DomainError`
   会让 `login_status` 把自己抛的「页面结构变了」当成「未登录」，永久掩盖 DOM 变化。
5. **改了立刻 commit。** 中间态（能 import、一运行就崩）留在仓库里比没有更糟。
6. **mock 的签名必须严格对齐真实契约。** mock 签名缺一个参数，100% mock 全绿，
   真机一跑就 `TypeError`。
