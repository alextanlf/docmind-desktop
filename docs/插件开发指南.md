# DocMind 插件开发指南

本文档面向想为 DocMind 写插件的开发者。插件层存在的理由是**体积**：不是应用必需、
也不是多数用户需要的能力，不该进安装包。远程知识库是这样一种能力，文档格式是另一种。

写完之后，你的插件会出现在设置页的**插件**分区里，用户可以搜索它、配置它、用它导入
文档——而 DocMind 的源码一行都不用改。

现有插件见 `backend/app/yuque/`（语雀）、`backend/app/feishu/`（飞书文档）。

---

## 30 秒上手

在你的包里声明一个 entry point：

```toml
# pyproject.toml
[project.entry-points."docmind.plugins"]
acme-tex = "acme_docmind:plugin"
```

```python
# acme_docmind/__init__.py
from app.document.formats import DocumentFormat
from app.plugins import DocumentFormatContribution
from app.schemas.imports import DownloadedDocument, ParsedDocument


def _parse_tex(document: DownloadedDocument) -> ParsedDocument:
    ...


plugin = DocumentFormatContribution(
    format=DocumentFormat(
        name="tex",
        label="TeX 文档",              # 文件选择器里的显示名
        media_type="text/x-tex",       # 内部身份键，解析按它分发
        extensions=(".tex", ".latex"),
        parse=_parse_tex,
    ),
    label="TeX 文档",                  # 卡片标题
    summary="把 TeX 源文件导入 DocMind",
    tag="文档格式",                    # 卡片上的分类标签，文案由你声明
    keywords=("latex", "论文"),
    version="0.1.0",
)
```

装上这个包，重启 DocMind。会出现三件互相独立的事：

1. 插件页多出一张「TeX 文档」卡片，搜 `tex`、`latex`、`.tex`、`论文` 都能命中；
2. 导入对话框多出一个「TeX 文档」按钮，文件选择器只列 `.tex` / `.latex`；
3. 导入 `.tex` 时后端会调用你的 `parse`。

客户端一行都没改——格式清单由后端 `GET /api/imports/formats` 提供。

## 概念：什么是一个插件

**一个插件 = 一个 entry point 返回的一个或多个「贡献」（contribution）。**

**一个贡献 = 一种可选能力**，它自己知道两件事：

| 方法 | 职责 |
|---|---|
| `install(host)` | 把自己装到该去的地方（provider 注册表 / 格式注册表 / 通知中心） |
| `cards(host)` | 为设置页描述自己，返回一个或多个卡片 |

加载器只会调用这两个方法，**从不问你是哪一种贡献**。catalogue 也只把每个贡献交出的
卡片拼起来。所以：

* 加一种新贡献 = 加一个类，**不需要改加载器、catalogue、API 层或渲染层**；
* 一个包可以同时交多种贡献——返回一个元组即可（例如同时提供远程知识库与格式）。

这条设计是刻意的：这两处的分派是**多态而不是 switch**。此前的形状要求贡献者必须是一个
实现了 12 个方法的远程 provider 外加一份凭据声明，所以「加一个格式插件」在当时无解。

### 卡片粒度

远程知识库的**一个卡 = 一个凭据通道**，不是一个 provider。`语雀网页登录` 和
`语雀 API` 是用户要**二选一**的两件事（开浏览器 vs 贴令牌），合并成一张卡就把这个选择
藏起来了。同理 `飞书账号授权` 和 `飞书机器人` 也不是一个东西的两项功能。

格式贡献自然是一张卡（一个格式就是一件事）；一个包提供多种格式就返回多个贡献。

## 可用的贡献类型

### 1. `DocumentFormatContribution` —— 文档格式

字段全部对应上例。几个要点：

* `DocumentFormat.extensions` 必须是小写、带前导点。校验在构造时就做，写错立刻报错。
* `single_file=False` 表示**可解析但不作为单文件提供**（内置的 HTML 就是这样：它能被解析、
  能出现在导入的目录里，但用户不能单独挑一个 `.html`）。默认 `True`。
* `binary_payload=True` 表示按二进制档的大小上限走（具体数值来自配置，你不要写死数字）。
* `magic=b"%PDF-"` 可声明前导字节，下载器据此拒绝「声明是 PDF 但签名不符」的流。
* `validate` 是一个 `bytes -> str | None` 的函数：返回错误文案表示这份载荷不是该格式，
  返回 `None` 表示没问题。分段存储、目录扫描、下载器都走它，所以你只声明一次。

**扩展名/媒体类型/内容类型别名冲突会直接报错**，不做静默覆盖。这是有意的：用户依赖
`.pdf` 现在的含义，插件不能劫持它。冲突会让你这个插件在插件页显示为「加载失败」并附上
原因——总比一个悄悄不生效的插件好，因为后者和「没装」在用户看来一模一样。

### 2. `RemoteSourceContribution` —— 远程知识库

```python
from app.plugins import RemoteSourceContribution
from app.remote.credentials import CredentialChannelSpec, ProviderCredentialSpec
from app.remote.provider import ProviderCapabilities, ProviderIdentity


class AcmeProvider:
    identity = ProviderIdentity(
        name="acme",
        label="Acme Wiki",
        summary="把 Acme Wiki 页面导入 DocMind",
        icon="library",
        keywords=("acme", "wiki"),
        homepage="https://acme.test",
        version="0.1.0",
        capabilities=ProviderCapabilities(),
    )

    async def close(self) -> None: ...


plugin = RemoteSourceContribution(
    provider=AcmeProvider(),
    credential_spec=ProviderCredentialSpec(
        provider="acme",
        channels=(
            CredentialChannelSpec(
                name="token",
                label="Acme 访问令牌",
                has_secret=True,
                default_secret_ref="acme:token",
                summary="用个人访问令牌读取 Acme Wiki",
                hint="在 Acme 后台生成一个访问令牌。",
                icon="key",
                keywords=("token", "令牌"),
                tag="知识库",          # 卡片上的分类标签
            ),
        ),
    ),
)
```

provider 侧要实现的 `RemoteProvider` 协议（定义在 `backend/app/remote/provider.py`）
与传输方式无关：官方 Open API、浏览器自动化、任何别的手段都行。

| 用途 | 方法 |
|---|---|
| 登录态 | `login_status()`、`begin_login()` |
| 知识库 | `list_repositories()`、`create_repository()` |
| 文档 | `list_documents()`、`create_document()`、`read_document()`、`update_document()`、`delete_document()`、`document_exists()` |
| 生命周期 | `close()` |

可选能力通过 `ProviderCapabilities` 声明，**不要**在客户端按厂商名分支：

```python
ProviderCapabilities(
    browser_install=False,         # 需要本地浏览器驱动登录，且能按需准备 WebDriver
    marker_lookup=False,           # 支持 find_document_by_marker（幂等写入的补偿机制）
    parent_node_write=False,       # 新文档可指定平台原生父容器
    browser_unavailable_code=None, # 缺浏览器时抛出的错误码，UI 据此显示安装按钮
)
```

`browser_unavailable_code` 必须由你声明、客户端不得硬编码。写死一个厂商错误码会让这个
组件对**所有其它插件**都是错的，包括还没被写出来的那些。

#### 凭据通道的其余字段

```python
CredentialChannelSpec(
    name="token",                 # 内部标识，存 keychain 与 URL 用
    label="Acme 访问令牌",         # 卡片副标题 / 输入框标签
    has_secret=True,              # 是否有密钥；False = 走交互式登录
    default_secret_ref="acme:token",       # macOS 钥匙串条目名
    tester=test_my_token,         # 异步 (secret) -> 账号标签 | None，失败抛 DomainError
    normalizer=normalize_my_url,  # 规范化/拒绝用户输入；SSRF 防线在这里
    secret_placeholder="粘贴访问令牌",
    help_url="https://acme.test/tokens",
    help_label="获取令牌",
    purpose="source",             # 机器可读："source" 提供文档 / "notify" 推送通知
    tag="知识库",                  # 上述 purpose 在卡片上的**显示文案**
    summary="…", hint="…", icon="key", keywords=(…),
)
```

`purpose` 与 `tag` 的分工：前者是机器可读的语义（凭据 API 会下发它），后者是卡片上显示的
文案。**文案由插件声明**，不由渲染层从 `purpose` 映射——那等于让页面知道每种用途叫什么，
而那是你的文案。`tag` 留空则不显示标签。

### 3. 通知（可选）

`RemoteSourceContribution.notifications` 接受一个 `NotificationTarget` 元组：

```python
from app.remote.notifications import (
    NOTIFY_ERROR, NOTIFY_INFO, NOTIFY_SUCCESS,
    NotificationEvent, NotificationTarget,
)


def build_my_target(credential_store):
    def _ready() -> bool: ...
    async def _send(event: NotificationEvent) -> None: ...
    return NotificationTarget(
        name="acme:webhook",
        send=_send,
        is_ready=_ready,
        severities=frozenset({NOTIFY_INFO, NOTIFY_SUCCESS, NOTIFY_ERROR}),
    )
```

它会注册进和内置插件**同一个** `NotificationHub`，所以业务代码只调 `hub.notify()`，
永远不需要知道消息发去了哪。投递永远是 best-effort。

## `cards()` 返回什么

`PluginManifest` 是卡片的读模型（定义在 `backend/app/plugins/manifest.py`）。其中：

* `id` 是卡片的稳定身份（`"<provider>:<channel>"`，无凭据通道的贡献用 `"<name>:core"`）。
  渲染层用它做 key，所以**改标签、改图标时不要改它**。
* `kind` 是渲染层唯一分派依据：它选的是卡片**主体**（凭据表单 / 登录按钮 / 静态说明），
  不是厂商。未知的 kind 会退回一张没有主体的中性卡片，而不是消失。
* `provider_label` 是副标题，回答「这个插件接进哪儿」，留 `None` 则不显示。
* `tag` 是分类标签的显示文案，见上。
* `extensions` 只有格式类贡献会用到，用来在卡片上列出「支持 .tex」。

`toolbar note`、搜索规则等都由 catalogue 从这些字段派生，你不需要关心。

## 图标键

`icon` 是一个字符串键，由前端解析成字形。目前可用：

| 键 | 用途 |
|---|---|
| `library` | 文档 / 知识库 |
| `key` | 需要密钥的凭据 |
| `login` | 浏览器登录 / OAuth |
| `bell` | 通知 |

传未知键不会崩——前端会退回一个中性的 `Puzzle` 图标。插件作为数据分发，字形表归前端所有。

## 声明信息：什么该你写，什么不该

**所有展示文案都由你声明**，前端和 API 层都不许拼：

- `label` / `summary` / `hint` / `placeholder` / `help_label` / `tag`
- `icon` / `keywords`
- 错误码 → 中文文案由 `electron/renderer/src/lib/client-errors.ts` 这个字典负责，
  但**平台专属的**错误码常量放在你自己的 leaf 模块里（例如 `app/yuque/codes.py`），
  放进 credentials 或 gateway 都会循环依赖。

一条判据：**文案映射表和安全白名单不算平台逻辑分支**。`isYuqueUrl` 这种域名白名单是安全
代码，别删；但 `if (provider === "yuque")` 这种是耦合，必须消除。

搜索也有同样的一条：卡片的可搜索字段由 `PluginCatalog._matches` 与
`electron/renderer/src/features/settings/plugin-filter.ts` 各持一份（跨进程无法共享），
两份**必须逐字段一致**——一个有、一个没有，就会出现「API 返回了但搜索框把它藏了」。

## 加载与故障

插件在应用启动时从 `docmind.plugins` entry point 组被发现，装进和内置插件**同一个**
`PluginHost`——所以它走的是完全相同的凭据 / 发现 / 导入 / 通知路径，没有「第三方专用分支」。

**加载失败不会阻止启动。** 一个坏插件只会让功能退化，不该让整个 app 打不开。失败会被收集，
并在设置页插件区底部以「以下插件加载失败」显示出来：

> 静默失败的插件和从未安装的插件在用户看来一模一样。不显示出来，就等于让用户没法区分
> 「这个集成坏了」和「这个集成不存在」。

同一个包里**先装成功的贡献会保留**；某个贡献失败会中断这个包的剩余贡献并记为失败。
贡献只有在 `install()` 成功之后才会被记入 catalogue，所以不存在「卡片在但功能不在」。

entry point 每次进程读取一次。装完插件需要重启，和装任何其他依赖一样。

## 返回什么

entry point 指向的可调用对象可以返回：

- 一个贡献对象
- 多个贡献（可迭代对象）
- 一个返回上述任一者的工厂函数（延迟初始化）

## 几条硬规矩

这些不是风格偏好，违反了会让插件在真实使用中出错：

1. **平台专属逻辑不许进 API 层或同步层。** 能力探测走 `ProviderCapabilities`，
   **禁止 isinstance**。远程绑定是 `(repositories.provider, repositories.remote_id)` 复合唯一。
2. **URL 类凭据必须走 `CredentialChannelSpec.normalizer`。** 这是 SSRF 防线——
   webhook 地址必须在保存前校验域名白名单，不要指望 API 层替你判断 `provider == "..."`。
3. **档位值 / 枚举值用厂商原生字符串，不要再套统一抽象层。** 但也不要把它们下发到前端
   让前端猜。
4. **捕获范围精确到具体异常类。** 把 `except SpecificError` 抄成 `except DomainError`
   会让 `login_status` 把自己抛的「页面结构变了」当成「未登录」，永久掩盖 DOM 变化。
5. **不要声明冲突的扩展名。** 会被拒，而且用户会看到你的插件加载失败。
6. **改了立刻 commit。** 中间态（能 import、一运行就崩）留在仓库里比没有更糟。
7. **mock 的签名必须严格对齐真实契约。** mock 签名缺一个参数，100% mock 全绿，
   真机一跑就 `TypeError`。
